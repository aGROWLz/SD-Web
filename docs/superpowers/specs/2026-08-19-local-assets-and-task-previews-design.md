# 本地素材与任务预览设计

## 目标

用户选择的图片、视频和音频在创建任务时先保存到项目本地。同一用户上传相同内容时按 SHA-256 复用同一文件；每个新任务都从本地原文件重新上传到 R2，外发请求不复用历史 R2 URL。创作任务卡显示受约束的素材预览。

## 本地素材

素材保存到 `uploads/assets/<userId>/<sha256>.<extension>`。任务参数使用 `local-asset://<sha256>.<extension>`，不包含绝对路径和其他用户标识。解析时必须同时提供任务所属用户，文件名只接受服务自身生成的哈希格式，从而阻止目录穿越和跨用户读取。

Data URL 在任务创建时解码并落盘。图片、视频和音频都采用相同机制，保证历史任务的编辑、重试和预览行为一致。相同用户、相同字节内容复用文件；不同用户仍保存到隔离目录。

## R2 数据流

任务创建阶段只保存本地素材并规范化参数，不上传 R2。队列处理任务时扫描 `local-asset://` 引用，读取本地文件并为当前任务逐项上传 R2，再将新公网 URL 仅写入本次外发请求副本。数据库中的任务参数继续保留本地引用，因此编辑或重试会再次上传。

没有 R2 配置时，图片仍可转换为 Base64 外发；音频和视频维持现有错误规则。旧历史任务中的 HTTP 素材 URL 不具备本地原文件，创作端编辑或重试时阻止提交并提示重新选择素材。

## 预览

新增 `GET /api/tasks/:id/assets/:index`，沿用任务鉴权与用户隔离规则，按内容下标定位本地素材并发送文件。前端使用现有 Axios 鉴权请求 Blob，再创建临时 Object URL。

任务卡在配置区域内显示小型媒体预览：图片使用裁切缩略图，视频使用静音元数据预览与控件，音频使用紧凑播放器。预览容器固定宽高并允许换行，不得撑破任务卡；加载失败显示对应素材名称和图标。

## 验证

测试覆盖 Data URL 落盘、哈希去重、用户隔离、路径校验、每次任务重新上传、旧 URL 阻止重试、预览接口权限以及三种媒体元素。完成后运行前后端全量测试和构建，并在桌面和窄屏浏览器中检查任务卡布局。

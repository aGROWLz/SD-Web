# 创作任务卡状态区与 R2 连通测试设计

## 目标

将一次视频生成收敛为一条任务记录：左侧展示任务配置，右侧使用固定方形区域承载生成状态、成片或失败原因。任务记录支持回填编辑和按原配置重试；管理员可独立测试已保存的 R2 Worker 配置。

## 任务记录与交互

每条记录保存提交时的完整 `CreateFormState` 深拷贝，包括提示词、模型、输出参数和素材 Data URL。提交中、排队中、生成中、已完成、失败均更新同一条记录，不再追加独立的助手消息。

左侧配置卡显示提示词、素材名称、参数摘要和任务编号，并提供“编辑”和“重试”按钮。编辑会把快照深拷贝回当前输入框并滚动到输入区，不触发生成；重试会基于旧快照新建一条任务记录，旧记录保持不变。为避免重复请求，提交中的记录禁用重试。

## 方形状态区

桌面端每条记录使用两列布局，左侧配置卡占剩余宽度，右侧为固定方形状态区。提交、排队和生成状态显示加载反馈；完成状态使用带控制条的 `video`；失败状态在方形区域内显示错误原因。移动端改为上下排列，方形区域保持比例并使用合理最大宽度。

## 实时状态

创作页监听现有的 `task:update`、`task:completed` 和 `task:failed` 浏览器事件，并按任务 ID 更新对应记录。创建接口返回后立即绑定真实任务 ID；若提交阶段失败，则直接把当前记录标记为失败并保留原配置供编辑或重试。

## R2 连通测试

管理员接口读取已保存并解密的 Worker URL 与 Key，通过 `GET /get-upload-url` 请求一个固定测试文件名。测试只验证 Worker 可达、鉴权成功以及响应中同时包含 `uploadUrl` 和 `publicUrl`，不执行 PUT，因此不会创建 R2 对象。外部 401/403、网络错误、HTTP 错误和响应格式错误作为结构化测试结果返回，前端在 R2 保存按钮旁展示独立的测试加载状态和结果。

## 验证

自动化测试覆盖任务快照深拷贝、状态归并、界面结构约束，以及 R2 测试的成功、鉴权失败、网络失败和无效响应。最后运行前后端全量测试与构建，并在桌面和移动视口检查任务卡、状态区和输入框没有重叠。

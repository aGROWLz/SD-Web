# Seedance 完整创作台与中转站管理设计规格

**日期：** 2026-08-19  
**状态：** 已确认  
**适用项目：** SD-Web

## 1. 目标

本次改造将现有演示性质的创作页面升级为可实际提交 Seedance 任务的专业工作台，并将分散的用户密钥模式改为管理员统一管理中转站。

完成后应满足以下结果：

- 用户可创建文生视频、首帧生视频、首尾帧生视频、全模态参考和样片任务。
- 前端参数名、取值与联动约束遵循 `SEEDANCE API.md`。
- 管理员维护多个仅在 Base URL 和 API Key 上有差异的兼容中转站，并指定唯一主站。
- 普通用户不接触中转站、URL 或 API Key；管理员通过用户级开关控制生成权限。
- 管理端具备可工作的中转站新增、编辑、启停、删除、主站切换和用户权限修改能力。
- 所有页面使用一致、响应式、面向工作流的视觉系统。

## 2. 现状审计

当前项目已有注册登录、任务列表、队列处理、实时状态、用户列表和平台 Key 列表，但以下功能不完整：

- 创作页面的素材上传未写入任务请求，实际只能生成纯文本视频。
- 前端使用 `generateAudio`，官方请求使用 `generate_audio`；水印、输出格式和任务类型等参数缺失。
- 任务处理器只提取少量参数，丢弃前端传入的其他设置。
- 用户传入的 `apiKeyId` 不在前端类型中，后端也会忽略并自行选择 Key。
- 「我的密钥」与管理员平台 Key 并存，不符合统一运营模式。
- 用户管理中的新增、编辑、删除按钮仍是提示信息；用户状态来自前端硬编码。
- 中转站 URL 固定在服务类中，无法通过后台切换。
- 管理员 Key 页面显示不存在的明文 Key、调用统计和图表数据，数据契约与后端不一致。
- 任务重试、历史按钮等入口没有可工作实现。
- 默认 Vite 样式与项目主题同时生效，造成全局宽度、排版和颜色冲突。

本次只保留有真实后端能力或本次会实现的入口，移除误导性的占位操作。

## 3. 信息架构

### 3.1 普通用户

- **创作：** 默认首页，专业创作台。
- **概览：** 使用统计和最近任务。
- **视频任务：** 搜索、筛选、查看、下载和删除任务。

普通用户不显示密钥或中转站入口。

### 3.2 管理员

管理员除普通页面外，增加「系统管理」分组：

- **用户与权限：** 查看用户、搜索筛选、切换生成权限。
- **中转站：** 管理名称、Base URL、API Key、启用状态和主站。

## 4. 用户创作台

### 4.1 布局

采用已确认的专业创作台方案：

- 页面顶部：标题、当前模式说明和创建状态。
- 主区左侧：模式切换、提示词、参考素材。
- 固定右侧检查器：模型、任务类型、分辨率、比例、时长、声音、水印和输出格式。
- 底部操作区：请求摘要、校验结果和「开始生成」按钮。

桌面端为双栏布局；窄屏下右侧检查器移动到主内容下方。所有控件保持稳定尺寸，不使用嵌套卡片。

### 4.2 生成模式

| UI 模式 | `content` 结构 | 关键约束 |
|---|---|---|
| 文生视频 | `text` | 提示词必填 |
| 首帧 | `text` + 1 个 `first_frame` | Seedance 2.5 比例固定为 `adaptive` |
| 首尾帧 | `text` + `first_frame` + `last_frame` | 首尾帧不可与参考素材混用 |
| 全模态参考 | 可选 `text` + `reference_image` / `reference_video` / `reference_audio` | Seedance 2.0 不允许只传音频 |
| 样片任务 | 1 个 `draft_task` | 不再混入其他 `content` 元素 |

全模态参考在 Seedance 2.5 下显示 `omni_reference_task_type`：`auto`、`reference`、`edit`、`extend`。`edit` 自动锁定 `ratio=adaptive`、`duration=-1`；`extend` 自动锁定 `ratio=adaptive`。

### 4.3 素材输入

- 图片：本地文件、HTTP(S) URL、Base64 或 `asset://` 素材 ID。
- 音频：本地文件、HTTP(S) URL、Base64 或 `asset://` 素材 ID。
- 视频：HTTP(S) URL 或 `asset://` 素材 ID，不提供虚假的本地直传入口。
- 本地图片和音频在浏览器中转换为 Data URL，并在提交前校验类型、数量和请求体风险。

本地图片支持 JPEG、PNG、WebP、BMP、TIFF、GIF、HEIC 和 HEIF；本地音频支持 WAV 和 MP3。视频 URL 对应 MP4 或 MOV，由上游服务执行最终媒体校验。

### 4.4 参数与模型联动

请求体统一使用官方字段：

- `model`
- `content`
- `omni_reference_task_type`
- `resolution`
- `ratio`
- `duration`
- `generate_audio`
- `watermark`
- `output_format`

Seedance 2.5 支持 480p、720p、1080p；Seedance 2.0 支持 480p、720p、1080p、4k；Fast 和 Mini 仅支持 480p、720p。Seedance 2.5 时长为自动或 4–30 秒，Seedance 2.0 系列为自动或 4–15 秒。

`seed`、`camera_fixed`、`frames`、`draft`、`return_last_frame` 和 `service_tier` 只属于旧模型能力，不在当前 2.5 / 2.0 模型选择中展示，避免向上游发送文档明确不支持的参数。`callback_url` 属于服务端集成配置，不暴露给普通用户。

## 5. 中转站与权限

### 5.1 数据模型

新增 `RelayStation`：

- `id`
- `name`
- `baseUrl`
- `apiKeyEncrypted`
- `isActive`
- `isPrimary`
- `createdAt`
- `updatedAt`

`User` 增加 `canGenerate`，默认允许生成。`Task` 和 `UsageLog` 关联 `relayStationId`，用于追踪任务实际使用的站点。

现有 `ApiKey` 数据不自动猜测 URL。迁移保留旧表，应用逻辑停止使用用户 Key；管理员需在新中转站页面创建有效站点。这样不会把未知来源的旧 Key 错误绑定到官方 URL。

### 5.2 主站规则

- 系统最多存在一个启用的主站。
- 设置新主站时，在事务内取消其他主站标记并激活目标站。
- 禁用主站前必须先选择其他主站，或明确让系统进入无可用站点状态。
- 新任务绑定提交时的主站；切换主站不迁移已排队任务。
- 队列按 `relayStationId` 隔离，处理器从任务关系中读取对应 Base URL 和加密 Key。

### 5.3 权限规则

- `canGenerate=false` 的普通用户可登录、查看历史任务和下载结果，但不能创建新任务。
- 管理员始终允许生成，避免误操作锁死管理账号。
- 前端禁用按钮仅用于反馈，后端必须独立执行权限校验。

## 6. API 设计

### 6.1 创建任务

`POST /api/tasks`

请求：

```json
{
  "prompt": "雨夜的未来城市",
  "params": {
    "model": "doubao-seedance-2-5",
    "content": [
      { "type": "text", "text": "雨夜的未来城市" }
    ],
    "resolution": "720p",
    "ratio": "16:9",
    "duration": -1,
    "generate_audio": true,
    "watermark": false,
    "output_format": "mp4"
  }
}
```

服务端不信任前端生成的 `content.text`，会用顶层 `prompt` 覆盖文本元素，随后执行模型能力和素材组合校验。

### 6.2 用户权限

- `GET /api/admin/users`
- `PATCH /api/admin/users/:id/generation-access`

权限接口只接受 `canGenerate: boolean`，并拒绝禁用管理员。

### 6.3 中转站

- `GET /api/admin/relay-stations`
- `POST /api/admin/relay-stations`
- `PATCH /api/admin/relay-stations/:id`
- `PATCH /api/admin/relay-stations/:id/primary`
- `DELETE /api/admin/relay-stations/:id`

列表只返回掩码后的 Key。编辑时留空 Key 表示保持原值；创建时 Key 必填。Base URL 去除末尾斜杠，服务端追加文档中的相对路径。

## 7. 管理端界面

### 7.1 中转站页面

页面使用高密度表格而不是卡片墙，包含：

- 名称、Base URL、Key 掩码、状态、主站、任务数和创建时间。
- 顶部显示站点总数、启用数和当前主站。
- 行内提供编辑、启停、设为主站和删除操作。
- 新增与编辑使用同一个对话框，Key 不回显明文。
- 无主站时显示高优先级告警，普通用户创建任务会收到明确错误。

### 7.2 用户与权限页面

- 显示邮箱、角色、生成权限、任务数和注册时间。
- 生成权限使用开关直接修改，管理员行固定为开启且不可关闭。
- 移除未实现的新增、删除和通用编辑入口。

## 8. 视觉系统

- 背景使用近黑与中性灰，强调色使用薄荷绿；状态色保留绿、黄、红和蓝。
- 不使用紫色渐变、圆形装饰或大面积营销式卡片。
- 圆角控制在 4–8 px；按钮、表格、输入框采用紧凑而清晰的工作台密度。
- 使用 Element Plus 图标，不手绘通用操作图标。
- 标题不随视口缩放，所有长 URL、邮箱和任务描述均提供截断或换行策略。
- 桌面端、平板和 390 px 手机宽度均不得出现横向内容溢出。

## 9. 错误处理

- 参数组合错误在提交前显示字段级中文提示。
- 后端返回稳定的中文错误消息和合适的 HTTP 状态码。
- 无权限返回 403；无主站返回 503；参数错误返回 400；资源不存在返回 404。
- 任务处理器保留上游错误信息到任务记录，但不向客户端泄露 API Key。
- 本地媒体转换失败、文件超限或不支持格式时，不创建任务。

## 10. 测试与验收

- 单元测试覆盖模型能力、素材组合、任务参数正规化、主站切换和生成权限。
- 服务层测试确认自定义 Base URL 与官方字段原样传递。
- 前端构建通过 TypeScript 检查。
- 浏览器验收覆盖普通用户创作、管理员中转站、用户权限、任务列表和登录页。
- 在桌面 1440×900、平板 1024×768、手机 390×844 下检查布局、溢出、空状态和禁用状态。

## 11. 完成标准

- 用户端不再出现「我的密钥」。
- 管理员可切换主站并控制普通用户生成权限。
- 完整多模态请求可从 UI 传到任务处理器，字段不被丢弃或错误改名。
- 所有可见按钮均有真实行为；不保留「开发中」提示入口。
- 自动化测试、前后端构建和关键页面浏览器验收均通过。
